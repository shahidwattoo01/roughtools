## What Is Statistical Significance?

Statistical significance is a way of measuring whether a result you observe in data is likely to be a real effect or just the result of random chance. When you run an A/B test, conduct an experiment, or analyze survey results, you are always working with a sample — and samples vary randomly. Statistical significance helps you decide whether what you measured reflects a genuine underlying difference.

The core concept is the p-value: the probability of getting your observed result (or a more extreme one) if there were actually no effect at all. A p-value of 0.05 means that if there were truly no difference, you would still see a result this extreme 5% of the time just by chance. When p falls below your predetermined threshold (alpha, commonly 0.05), you call the result statistically significant.

This does NOT mean the result is large, important, or definitely true — only that it is unlikely to be pure chance at the significance level you chose. A tiny conversion rate difference on a website with millions of visitors can be highly statistically significant while having essentially no practical value.

Statistical significance testing is standard practice in A/B testing platforms, clinical trials, academic research, and quality control processes. Most decisions about product changes, medical treatments, policy interventions, and manufacturing processes rely on significance testing to filter signal from noise. Understanding what it does and does not mean is essential for interpreting data correctly.

## Key Concepts

**P-value:** The probability of observing results at least as extreme as yours if the null hypothesis (no effect) were true. p=0.03 means there's a 3% chance of getting these results by random variation alone. Does not equal the probability the result is true.

**Alpha (α):** The significance threshold — the acceptable false positive rate. Standard: α=0.05 (5% false positive rate). More stringent: α=0.01. For medical/safety decisions, α=0.001 or lower.

**Statistical Significance:** When p < α. "Significant" in statistics means "unlikely to be due to chance" — NOT "large" or "important."

**Confidence Interval (CI):** The range within which the true effect likely falls. A 95% CI of [+1.2% to +3.8% conversion rate increase] means you're 95% confident the true effect is within this range.

**Statistical Power:** The probability of detecting a real effect when one exists. Standard target: 80% power. Low power means you might miss real effects (false negatives).

## Two-Proportion Z-Test (for Conversion Rates)

For A/B tests comparing conversion rates:

```
z = (p1 − p2) / √[p̂(1−p̂)(1/n1 + 1/n2)]

Where:
p1 = Conversion rate of Control
p2 = Conversion rate of Variation
p̂ = Pooled conversion rate = (Conversions1 + Conversions2) / (n1 + n2)
n1, n2 = Sample sizes
```

**Worked example:**
- Control: 1,000 visitors, 52 conversions (5.2%)
- Variation: 1,000 visitors, 68 conversions (6.8%)
- p̂ = (52+68)/(1000+1000) = 120/2000 = 0.06
- z = (0.068 − 0.052) / √[0.06 × 0.94 × (1/1000 + 1/1000)]
- z = 0.016 / √[0.0564 × 0.002] = 0.016 / 0.01061 = **1.51**
- p-value (two-tailed) ≈ 0.13 → **Not statistically significant at α=0.05**

With only 1,000 visitors per group, the test is underpowered to detect a 1.6 percentage point difference at p<0.05. Need ~4,000 per group for 80% power with this effect size.

## Required Sample Size Calculation

Before running an A/B test, calculate how many visitors you need:

```
n = 2 × (z_α/2 + z_β)² × p̄(1-p̄) / (p1-p2)²
```

For α=0.05 (two-tailed), 80% power: (z_α/2 + z_β)² = (1.96 + 0.84)² = 7.84

## Frequently Asked Questions

**What does p < 0.05 actually mean?**
If the null hypothesis (no difference between control and variation) were true, you would see a result this extreme or more extreme only 5% of the time (1 in 20 experiments). p < 0.05 does not mean: "There's a 95% chance this result is true"; "The effect is large or important"; or "This study will replicate." It's a decision threshold to distinguish signal from noise, not a guarantee of truth.

**How long should I run an A/B test?**
Run the test until you reach your pre-calculated required sample size — stopping early when results "look significant" is called peeking and inflates the false positive rate. Run for at least one full business cycle (typically 2–4 weeks for most websites) to account for weekly seasonality. Don't run indefinitely — the longer a test runs, the more chances for external confounds. Set sample size and duration in advance, then run and read.

**What is the difference between statistical and practical significance?**
A result can be statistically significant without being practically meaningful. A website with 1 million visitors per week might show that a button color change produces a 0.01% conversion rate increase with p=0.0001 — statistically significant, but worth the engineering effort for 100 extra conversions per week? Practical significance asks: even if the effect is real, is it large enough to matter? Effect size measures (Cohen's d, relative lift %) help assess practical significance alongside p-values.

**Why do I need to calculate sample size before the test?**
Running a test until you get a significant result — then stopping — produces false positives at much higher than the nominal rate. If you check your test daily and stop when p<0.05, your actual false positive rate may be 20–30%, not 5%. This is the "peeking problem." Determine sample size required before starting, commit to running the test until that sample size is reached, and then read the result once.

**What is Bayesian A/B testing?**
Frequentist A/B testing (described above) uses p-values and fixed sample sizes. Bayesian A/B testing uses probability distributions to continuously update beliefs as data arrives, allowing more natural early stopping with proper statistical controls. Bayesian approaches output "probability that variation is better" rather than p-values. Both approaches are valid; Bayesian is gaining popularity in industry because the output is more intuitive. Most major A/B testing platforms (Optimizely, VWO) offer both approaches.
